本文件夹给接手的人（或 AI）继续研究用。包括：查过什么、各预设的数据从哪里来、怎么核对的、哪些是我方假设、哪些结论被实测推翻过，以及还没做完的方向。使用说明见上一级的 `HANDOFF.md`，本文只讲研究。

## 0. 先把工作区还原出来

安装后的扩展里只有插件本身能跑；处方生成器和测试在 `research/kit/` 里，需要先还原成源码树的布局：

```bash
python3 <扩展目录>/research/kit/setup_workspace.py ~/BlenderLensWork
cd ~/BlenderLensWork
python3 tests/test_optics.py && python3 tests/test_flare.py && python3 tests/test_presets.py
python3 tools/build_presets.py          # 由专利转录数据重新生成 E/G/Panavision 预设 JSON
BLENDER=/path/to/Blender zsh tests/run_all.sh   # 全套（含 Blender 渲染验证，CPU 约 1–2 小时）
```

## 1. 结论先说

- **Panavision C / E / G / T / Primo 变形系列的量产处方从未公开。** Google Patents 上转让给 Panavision 的变形相关专利逐份查过（见 §2），只有 US 7,085,066 带完整数值表。
- 所以 C / E / G 三个预设是「同年代、同结构的公开专利 + 按 Panavision 公布的规格设定观感参数」，**不是复刻**。
- **US 7,085,066 是唯一的真 Panavision 变形处方**：Iain A. Neil 设计的后置 1.34× 变形组，接在 US 6,122,111 的变焦镜后面。两个 Panavision 预设（短焦端 Z1、长焦端 Z4）都是原样收录。
- 早期文档说 US 2,890,622 和 US 5,650,880 是 Panavision 处方，这不成立：前者是 Wallin 的反向旋转柱面机构，没有数值；后者与变形镜头的关系无法核实。

## 3. 各预设的数据来源与假设

### 3.1 C 系列风格（Rosin 前置 2× + Nikon f/2，垂直 50 mm）

- 主镜按 f = 100 归一化后乘 0.5。
- 对焦用双组联动：整体单元移动 Δ1，变形器前组再多移 Δ2（改变柱面组间距）。这是老式前置变形器的典型做法，所以发腮明显。
- **我方假设**：
  - 光阑轴向位置：专利没给，取 P6–P7 空气间隔中点（z ≈ 50.03 mm）。
  - 变形器到主镜的间隔 A8.d = 5 mm。
  - 玻璃只给 n_d / V_d，色散用 Cauchy 近似换算。

### 3.2 E 系列风格（Isco 实施例 3 原尺寸 + Nikon f/2 原尺寸，垂直 131 mm）

- **间隔取对焦表的「infinite」行**：E(3) = 96.425、E(9) = 57.780。主表里的 100.224 / 51.328 对应约 6 m 合焦。
- 对焦按专利的凸轮：中间两组（I4–I9）移动 Δ2；后组 I10–I12 与主镜跟随移动 Δ1；前组 I1–I3 相对焦面固定。
- 解挤压用光学实际值 2.09，按名义 2.0 解挤压会窄 4.5%。
- 这个附加镜是长焦设计。配 f = 100 主镜时，S35 变形画幅的垂直半视场只有约 4°。缩到 50 mm 会超出设计视场 2.6 倍，镜片边厚变负，所以 E 取 135 mm 档、G 取 100 mm 档。

### 3.3 G 系列风格

与 E 的光学相同，整体缩放 0.763 到垂直 100 mm（视场比原设计大约 30%）。

### 3.4 Panavision 后置 1.34×（Z1 短焦端 / Z4 长焦端）

- **前 46 面**是 US 6,122,111 的变焦镜，**S47–S60** 是后置变形组；口径用专利给出的最大通光高度（`aperture_source: patent`）。
- **玻璃**：专利只给六位 Ohara 代码（n_d 三位、V_d 一位），用 Ohara 目录值替代。老牌号取 OHARA 2017 Zemax 目录（refractiveindex.info），S- 牌号取 oharacorp.com。FPL53 在专利里印成 438950，目录是 439950。
- **变焦**：TABLE 1 的 Z2–Z4 间隔不能直接替换。专利两张表的 Z1 不一致：S39 在 6,122,111 里是 0.600，在 7,085,066 里是 0.100，因为后者接了变形组。做法是把 6,122,111 里 Z_n 相对 Z1 的**差值**叠加到 7,085,066 已核实的 Z1 表上。
  - 结果：变焦镜单独在 Z4 为 49.22 mm（专利 49.2）。
  - Z4 下系统焦距 x/y 50.850 / 66.370，压缩比 1.3052，BFL 35.904。
  - Z2 / Z3 的间隔也在 `PV_ZOOM` 里，还没做成预设。
- **对焦**是变焦镜自身的内对焦：前组（第 1–2 片，S2–S5）移动 Δ，第二组（第 3–4 片，S6–S9）移动 0.9088·Δ，变焦组与后置变形组不动。
  - 位移比取自 TABLE 1：F2 时 S5/S9 间隔各增 1.022 / 10.077，F3 时各增 1.960 / 19.724，比值 0.908 / 0.910，取平均。
  - 中间像位置不变，所以两向同时合焦，压缩比不随对焦变化（无发腮）。这是后置设计与前置设计最大的画面差别。
  - **物距定义**：TABLE 1 的「Object」厚度从物面量到 S1。S1 是 S2 前 1 mm 的虚面，随前组移动。按此定义模型复现了专利行程：F3（133 mm）前组 21.686 mm，专利 21.684；F2（330 mm）11.221 mm，专利 11.099（1%，因为位移比用了平均值）。
  - 注意：专利正文说 F2 时 S5/S9 为 7.260 / 14.508，与表不符（表中 7.260 是 F3 的值）。以表为准。
- **最近对焦**取专利 F3：物面到 S1 133 mm，距像面 476 mm。
- **长焦端口径**（0.4 修正）：7,085,066 TABLE I 的通光高度只是 Z1、f/3.66 下的光束高度。长焦端如果照用，轴上光束会被切掉 55%，实际最大光圈只有约 f/6。6,122,111 的权利要求 35（即 TABLE 1 末列）给了变焦镜各面的**最大通光直径**：f/2.2、像高 14.45，「for all Focus and Zoom Positions」，相当于镜片实物尺寸。Z1 以外的变焦位置改用这张表。
  - 改后长焦端的轴上通过率为 0.755，与 Z1 的 0.758 相同，剩下的差别只来自椭圆出瞳。
  - 不相撞；后置组仍用 7,085,066 的值。
  - 光阑：6,122,111 是恒定 f/2.2 的变焦镜，光阑直径随变焦调整（f/2.2 时 Z1 29.30、Z4 40.98 mm）。7,085,066 在 Z1 把它缩到 21.02 mm（f/3.66 综合），按同一比例，Z4 应为半径 14.70。我们按「系统垂直 f/4.10」近轴推出的是 14.56，二者一致。
- **画幅与光圈**：画幅 16:9（23.71 × 13.34，像高半径 13.60）。专利规定整幅 2.40:1 装进 16:9，真实追迹的画面边缘张角比 2.401，所以解挤压用 1.35。Z1 用专利的 f/3.66 与光阑半径 10.51；Z4 按垂直 f/4.10 求光阑。

### 3.6 Neil 2× 现代变形（CN 111562632 B，0.6）

- 数据：中国授权本第 28–30 页表 1–3，逐位读出后写进 `tools/build_presets.py`（`NEIL_FRONT` / `NEIL_FOCUS` / `NEIL_REAR`）。
- 前变形部分对三个焦段相同（专利原文这样说，三张表也一致）；后组与前后间隔（4.700 / 12.789 / 4.720）不同。
- 对焦：G1b（L3–L4）整体移动。两侧间隔之和在三个对焦位置都是 17.796–17.797 mm，证明是整体移动。
  - 一个自由度同时对准两向：X 残差 ≤ 0.07 mm。
  - 近轴求解的行程比专利多 2–4%（FD2 3.31 vs 3.17，FD3 6.54 vs 6.39 mm），三个后组都一样，来自前组。专利按弯曲像面上的最佳聚焦定位，像方相差约 0.05 mm，在 f/3 景深以内，不调。
- 压缩比随对焦变化：2.06 → 1.93（最近对焦 1.08 m，−6.6%）。比 C 系列风格（−16%）和 Isco（−22%）温和得多，这是这个设计的目标。
- 像面：专利把像面设成随对焦变化的 X/Y 柱面，「以模拟弯曲物面」。这里用平面传感器，所以边缘带这个设计本身的场曲。
- 解挤压用近轴值 2.06。最近对焦取 FD3：物面到第一面 868 mm，距像面 1078 mm。
- 这不是 Panavision 镜头，是 Panavision 后置变形组的同一位设计者给思锐做的设计。

## 4. 主要数值结果（真实光线追迹，tests 里都有对应测试）

| 量 | C | E | G | PV Z1 | PV Z4 |
|---|---|---|---|---|---|
| 压缩比 ∞ → 最近对焦 | 2.011 → 1.687 | 2.094 → 1.632 | 2.094 → 1.652 | 1.304 不变 | 1.305 不变 |
| 发腮（同放大率，物距 = 20 × 垂直焦距） | −12.9% | −9.9% | −9.9% | 0 | 0 |
| 压缩比随视场（中心 → 边缘） | 2.01 → 2.27 | 2.09 → 2.13 | 2.09 → 2.16 | 1.30 → 1.35 | — |
| 角落 95%/90% 视场光瞳通过率（猫眼） | 0.64 | 0.84 | 0.90 | 0.68（专利称角落相对照度约 50%） | — |

- **Isco「低发腮」**：专利正文说的「约 4%」，是相对于对焦表中段参考距离（约 6 m）的偏差。从无穷远到 2.5 m，实际变化约 10%。同放大率下比 Rosin 少约四分之一。
- **焦外高宽比 ≠ 压缩比**：C 系列风格的背景焦外解挤压后约 1.5，前景焦外约 3.1。渲染与追迹吻合到 1% 以内，属于「靠改变柱面组间距对焦」这种结构的性质。可以用 `optics.bokeh_aspect()` 计算。

## 5. 修正记录（推翻过的结论，避免重蹈）

1. **「f/2 时角落光斑只剩中心 62%」是错的。** 那是按光斑面积阈值量的，被噪点和离轴彗差拖尾干扰，当时也没有用独立预测核对。改用能量指标，并为每个预设设定角落光瞳通过比例（C 0.40 / E 0.55 / G 0.75），口径按此反推。
2. **「Isco 低发腮不成立」说过头了。** 同放大率比较，Isco −9.9%，Rosin −12.9%，确实更低，只是没有专利正文说的那么低。
3. **US 2,890,622 是 Panavision 的专利**（Wallin），但它没有处方。早先「不是 Panavision」的说法错了。
4. **Z4 变焦间隔不能照抄 6,122,111 的绝对值**，否则 Z1 自身就错了（S39 0.600 对 0.100）。要叠加差值，见 §3.4。
5. **Panavision 对焦**：最初按整体移动近似，长焦端在 3 m 有 0.69 mm 的水平残差，映射误差到 0.9 px。改成专利内对焦后残差为 0，映射误差降到 0.22 px。之后一度以为行程与专利相差 4–13%，原因是把物距错当成从像面量起；按专利定义（物面到 S1），F3 吻合到 0.01%。
6. **Cycles 薄膜在 IOR < 1 时不正确。** 100 nm MgF₂ 在 IOR 1/1.6 时透过率只有 0.76，正确值 0.99。界面法改为 IOR 恒 ≥ 1，并翻转玻璃→空气面的法线。
7. **鬼影 / 几何模式必须关自适应采样**，否则鬼影被低估约 8 倍。
8. **Cauchy 换算**：原设计文档的公式错了约 5000 倍。正确式 B ≈ (n_d − 1) / (1.910 · V_d) μm²，N-BK7 得约 0.0042 μm²。
9. **长焦端口径**（0.4）：见 §3.4。是在做出瞳重要性采样时发现的：均匀白环境下，长焦端轴上亮度只有 0.34。
10. **统一焦段缩放没有缩放最近对焦距离**（0.3 的错误，0.4 修正）：Panavision 短焦端放大 4.85 倍后，最近对焦仍是 476 mm，物体落在镜头里面，对焦求解除零。现在最近对焦随镜头等比缩放。
11. **曝光归一化**（0.4）：OSL 原本假设「采样盘上的近轴出瞳 = 真实出瞳」，并据此把轴上满光瞳归一到 1。光阑后有柱面时，真实出瞳是椭圆，而采样盘按两截面取大，Panavision 两个预设因此暗了 0.39 档：真实/估计面积 0.765 ≈ 1 / 压缩比。
    - 现在 Build 时追迹测出这个比值并除掉。只在光阑限光时测（光阑缩到一半），所以最大光圈下其他镜片的物理切光照常保留。C 系列在 f/2.0 时轴上就有 16% 被切。
    - C / E / G 的变化不到 1%。

12. **US 11,287,618 的表格不能用**（0.6）。按美国本建模，50 mm 实施例算出来 FLY = −36.7 mm，后组几乎无光焦度（EFL 2990 mm）。
    - 先排除了别的原因：符号约定翻转、间隔错行、1024 种后组半径符号组合，都对不上。
    - 再用边厚判定：只有 S10 一处在口径边缘会穿过下一片。
    - 用「前组 + 一片理想薄透镜」反解，得到前组本身是对的（f₂ ≈ 51 mm 就能得到 50 / 25 mm），问题在后组的印刷数据。
    - 同族的中国授权本 CN 111562632 B 给出了干净的原始表格，对比可以看出美国本的错误：
      - 玻璃代码 / 名称不存在（547238、58486、AP7816、SYGH31、SLA3156……）；
      - 表 2 后组的间隔整列照抄表 1；
      - 表 2 / 表 3 后两片的 Y 半径照抄表 1；
      - S10 印成 +41.527（应为 −51.827）、S24 印成 −195.007（应为 −105.007）；
      - S8 在 FD2 处标成 FD1、FD3 的间隔 5.677 应为 8.677。
    - 教训：同一发明的不同国家公报是独立排版的，一份对不上时先找同族。美国本的分析脚本留在 `research/analysis/us11287618_neil_reconstruction.py`。

13. **杂光指数不对**（0.6 / 0.7 的错误，0.8 修正）。预设的 `veiling_glare` 说是 ISO 9358 杂光指数，但实现把它直接当散射能量比例：用白场中央黑斑（直径为画面高度的 10%）合成测试，测出的 VGI 只有设定值的约 1/4。另外 FFT 卷积是环绕的，右边缘的亮光会漏到左边缘。0.8 改为补零线性卷积 + 均匀雾化项，并按合成测试反解散射比例，测出值与设定值相差 < 1%。
14. **Geometry 模式一直没有光圈**（0.1 起，0.8 修正）。几何模式的光线只受 OSL 出瞳采样盘（1.4 倍近轴出瞳、放在出瞳平面）和镜片口径限制，f 值与叶片数对它几乎无效——它校验的其实是另一套光学系统。0.8 加了光圈网格（`BL_Iris`，叶片多边形与 Analytic 同一判据，随对焦组移动，改 f 值 / 叶片时重建）。Panavision 长焦端 Geometry − Analytic 的残差因此从「随视场变化（水平 +0.42 → +0.15 px）」变成全画面一致。
    - 另外两处法线精度也修了，但实测都不是残差主因：① `normals_split_custom_set_from_vertices` 把法线压成 16 位角度（回读误差最大约 100″）→ 改用浮点「自由法线」；② Cycles 把顶点法线压成八面体 16+16 位，恰为 0 的分量一律解码成 +1.5×10⁻⁵（平面、柱面因此带一个指向 +x / +y 的微小棱镜）→ 平面改平直着色，其余把 0 分量按顶点交替写成 ±1e-12。两项修前修后残差变化 < 0.01 px。
    - **仍未解决**：Panavision 长焦端 Geometry 比 Analytic 整体平移约 (+0.27, −0.40) px（270p，15 个点一致）。已排除：网格密度（加密 4 倍不变）、薄膜（关镀膜不变）、物体偏心 / 倾斜（逐个检查，< 1e-4 mm / 1e-6）、相机坐标系偏移（单片球面镜 Geometry = Analytic）。

15. **「C 系列风格」的发腮不是 C 系列的特征**（0.1 起的表述，0.8 更正）。Panavision C 系列（1968）是发腮已校正的（Auto Panatar 一脉，1958 年获科技成就奖）；ARRI Master Anamorphic 数据表在最近对焦时 H/V 放大率之比仍为 2.00 ± 0.03。我们的 2.01 → 1.69 是 1950 年代未校正前置变形器的行为。0.8 加了补偿板并默认开启（§6.9）。

## 6. 方法要点

- **坐标与符号**：原点在像面，物方 +Z，光沿 −Z；单位 mm；面形 z = z_顶点 − sag；R > 0 表示曲率中心在像方。柱面用 R_x 或 R_y = null 表示。
- **对焦求解**：两个自由度（两组系数 c1、c2），水平、垂直两向同时用 Newton 求解，目标是各向的无穷远像位置。Panavision 是单自由度、只解 Ry；由于内对焦，Rx 自动合焦，测试会检查 Rx 残差。
- **口径**：真实光线追迹，在看片光圈下取传感器 9 个视场点 × 光阑边缘 48 点；角落光瞳按 corner_pupil_fraction 线性渐晕；再做镜片边缘相撞检查与收缩。改了几何要重跑 `rebuild_apertures.py`。
- **映射验证**：用 3 m 刻度靶，比较渲染的竖线 / 横线质心与 Python 主光线追迹的预测。
  - Analytic ≤ 0.6 px。
  - Geometry ≤ 1.2 px，是全画面同号的亚像素平移，长焦端最大。原因未查明，见 §7。
- **炫光**：前向追迹所有镀膜面对的两次反射，单层 MgF₂ 按 R/G/B 用 Airy 公式；按 Cycles 直射能量归一化，再按密度做各向异性泼溅。与相机端鬼影（8192 spp，关自适应）交叉验证：光晕/光源比 0.085 vs 0.078。

## 6.5 0.4 的采样改动（回应外部改进建议）

- **出瞳重要性采样**（`pupil.py`）：
  - 对传感器一个象限的 11×9 网格点、3 个波长（400 / 550 / 700 nm）、3 个对焦状态（∞、最近对焦、2.5 倍最近对焦），追迹出瞳平面上能穿过镜头的采样点，取包围盒，再向 3×3 邻域膨胀并加余量。
  - OSL 按 |sx|、|sy| 双线性插值后镜像到本象限，在盒内均匀采样；盒外的盘内区域仍算挡光，权重乘「盒面积 / 盘面积」，所以与原估计器是同一个积分。
  - 盒面积不小于采样盘（例如收光圈后）时退回整盘采样。
  - 开鬼影或 Geometry 模式时不用：鬼影路径会穿过盒外区域。
  - 渲染实测（`tests/bl_sampling.py`，均匀白环境，32 spp 对 1024 spp 参考）：
    - 开 / 关的各区域亮度一致到 0.04%，无偏。
    - 同等噪点所需采样减少到 1/1.78（C，最大光圈、无穷远）、1/1.53（C，最近对焦）、1/1.44（Panavision 长焦端）；收到 f/8 时与原来相同（自动退回整盘）。
    - 外部建议估的「2–4 倍」偏乐观：盒子对圆形通光区的上限是 π/4，又要罩住多个波长和对焦状态的并集。
    - 更紧的形状（椭圆 / 凸多边形）或按对焦状态分表，是继续提升的方向。
  - 覆盖性测试 `tests/test_pupil.py`：随机视场 × 400–700 nm × 6 个对焦距离（其中 3 个不在表里），5 个预设共约 47 万条穿过镜头的光线，全部落在盒内。
- **连续波长色散**：400–700 nm，按三条高斯传感器响应之和做重要性采样（5 nm 分段逆 CDF）。每条光线同时贡献给 R/G/B，权重非负，等能白光仍为白（测试到 1e-9）。
  - 单通道权重的二阶矩从 3.0（旧的三选一）降到 2.0–2.7，三色分离环变成连续色边。
  - 另有 `dispersion_strength`（0–1），在 n_d 与真实 n(λ) 之间插值。
- **第三维随机数**：实测 Cycles 的 OSL 相机 `camera_shader_random_sample()` 只有两维有效（第三维恒为 0），所以波长只能用随机数与像素位置（含亚像素抖动）的哈希。

- **收敛性**（回应外部建议 §7.5「真实场景 4× 采样噪点只降 1.5×」；`tests/bl_convergence.py`，棋盘格 + 13 个很小很亮的焦外点光源，64 → 256 spp）：

  | 设置 | 原始噪点下降 | x/(1+x) 压缩后的下降 |
  |---|---|---|
  | 色散开，自适应开 | 2.22× | 1.78× |
  | 色散开，自适应关 | 2.22× | 1.79× |
  | 色散关，自适应开 | 2.20× | 1.34× |
  | 色散关，自适应关 | 2.20× | 1.37× |

  - 原始噪点在所有组合下都按 1/√N 收敛（理论 2×，分层采样略好于理论）。
  - 第三维随机数用哈希不影响收敛（色散开 / 关一样），自适应采样在这个场景也没有影响。
  - 同一组渲染，压缩后的指标只有 1.3–1.8×。原因是 x/(1+x) 是非线性变换：亮像素上的噪声被压扁，而且压扁的程度随 spp 变化。所以用压缩指标比较不同 spp，会系统性地低估收敛速度。建议用原始值，或按亮度分段（例如只统计 < 1 的像素）比较。
  - 真实场景若原始指标也不到 2×，再查萤火虫（小而极亮的焦外光源）和 Cycles 的 clamp 设置。

## 6.6 0.5：GPU 路径与渲染时间（回应 MessyRoom 的 0.5 需求）

- **GPU（A-lite）**：在 Blender 5.3 / M2 Max 上实测以下几点，细节见 HANDOFF 第 6.5 节。
  - Cycles 的 Metal 内核在运行时从源码编译；
  - `_cycles.init(<路径>)` 可以让 Cycles 改读另一份源码；
  - 自定义相机在 GPU 上走 `camera_sample_custom()` 的非 OSL 分支（原本 `return zero_spectrum()`）；
  - 只把这个分支换成生成的 C++ 追迹，就能在 Metal 上跑整支镜头，不需要编译 Blender。
  - 合成基准 256 spp：GPU 1.23 s，0.5 CPU 23.0 s，0.4 CPU 69.7 s；GPU 与 OSL 的刻度靶误差完全相同。
  - 每帧参数经 KernelCamera 里自定义相机不用的字段传入：convergence_distance、fisheye_fov、inv_aperture_ratio、blades 实测原值到达；bladesrotation 与 focaldistance 会被宿主改写，不能用。
- **CPU 上镜头追迹并不便宜**：只有镜头、没有场景几何时，960×540、256 spp 要 22 s，普通相机 1.8 s。合成基准的 CPU 时间几乎全在 OSL 相机里。
  - 改成解析求交后，CPU 从 69.7 s 降到 22.9 s（3 倍），噪点与平均亮度逐位相同。
  - 真实场景里场景着色占比更大，所以 MessyRoom 测到的镜头开销只占 27%。
- **解析求交的数值稳定写法**：在顶点平面上写二次方程 c(x² + y² + w²) + 2w = 0（w 从顶点量起），取靠近顶点的根 u = −2C / (B + sign(B)√Δ)。
  - 这样既避开 float32 下大半径（14624 mm）球面的抵消误差，也自动选对半球。
- **色散的噪点**：横向色差只依赖主光线，可以后期精确加上（`lenspack.py`：每个传感器点、每个波长，取射向出瞳中心的光线到物面，再用 d 线映射的牛顿反解得到源像素）。
  - 实测彩边位置与逐采样色散相差 ≤ 0.11 px，色噪降低约 45 倍。
  - 纵向色差（焦外彩边）仍需逐采样。
  - 「按像素内采样序号分层波长」做不到：OSL 相机与 GPU 自定义相机都拿不到采样序号，只有两维随机数。
- **曝光**：同机位比普通相机暗 0.31–0.36 档，几乎全部来自渐晕 × cos⁴（中心只差 0.02 档）。`api.exposure_vs_pinhole` 的预测与实测相差 ≤ 0.01 档。

## 6.7 0.6：目录色散、衍射星芒、杂光

- **目录色散**：`glass/ohara.json` 汇编了 refractiveindex.info（CC0）的 410 种 Ohara 玻璃（Sellmeier / 多项式公式、nd、Vd、代码，公式重算 nd 误差 ≤ 5e-7；`tools/glass_catalog.py` 生成）。
  - 有目录数据的玻璃拟合成 n = A + B/λ² + C/λ⁴ + E/λ⁶（400–700 nm，锚定 nd），预设所用 35 种玻璃误差 ≤ 2.6e-5。这个形式在 OSL / GPU 里只多两次乘加。
  - 旧的两项 Cauchy（由 nd / Vd 换算）对重火石在 400 nm 偏差最大 8.7e-3（S-TIH53），紫边位置因此不准；改后约小 300 倍。
  - 老专利只给 nd / Vd 的玻璃（Rosin、Nikon、Isco）仍用两项 Cauchy。
  - 只有三项（A + B/λ² + C/λ⁴）时，重火石误差仍有 7.5e-4；加 Dλ² 也只到 7.7e-4（全目录最坏），加 E/λ⁶ 才够。
- **衍射星芒**：光圈多边形（与 OSL 相机同一判据）的夫琅禾费衍射，FFT 2048²，光瞳边缘按有符号距离抗锯齿。阶梯状边缘会衍射出平行的假星芒，这一步不能省。
  - 像面上按 λ/(2·NA) 缩放，两向的 NA 由追迹的光束张角量出，所以变形镜头的星芒会被拉伸。
  - 能量按该光源在 Cycles 里的直射像总能量归一化，去掉 Airy 主斑（渲染里已有）。f/8 时主斑外约占 11–17%，与圆孔理论值 16% 同量级。
  - 强离焦的光源以焦外为主，星芒按几何光斑半径淡出。
- **杂光**：保能量的长尾核（(1 + r²/r0²)^(−1.3)）。只由表面反射率推算比例不可靠：单层膜 0.5–3%，但无镀膜给出 12–41%，因为杂光主要来自镀膜去不掉的散射。所以改成每个预设的观感参数，按 ISO 9358 杂光指数典型值取：C 2.5%、Panavision 后置 1.2%、E 与 Neil 0.8%、G 0.5%。

## 6.8 0.7：Schott 目录与 Isco 谱线、GPU 鬼影、Neil 场曲

- **Schott 目录**：refractiveindex.info 的 156 种 Schott 玻璃汇编为 `glass/schott.json`。
  - 源数据里有 3 种（N-LAF32、N-LASF31、N-LASF46）的 Vd 字段有误，但公式算出的 nd 正确，本项目只用公式。
  - 处方玻璃用 `"catalog": "SCHOTT:SF11"` 指定厂商。
- **Isco 玻璃**：专利给了 d / C / F 三条谱线。
  - SF 11 与 Schott SF11 相差 ≤ 5×10⁻⁶，400 nm 处的折射率从两项近似的 1.8382 改为 1.8451（差 0.007）。
  - LaF N21 是含铅老牌号，现行的无铅后继 N-LAF21 与之相差约 2×10⁻⁴。所以取 N-LAF21 的曲线形状，再加 a + b/λ² + c/λ⁴ 使其精确通过专利的三条谱线。
  - 一般规则：专利给了 n_C / n_F 的玻璃（`glass["n_C"]`、`glass["n_F"]`），都按专利谱线校正目录曲线。
- **GPU 相机端鬼影**：OSL 的两次反射状态机原样移植进 GPU 内核（随机选面对、无偏权重、单层 MgF₂ 薄膜按 R/G/B）。
  - 实测（窗户类大面积亮源，2048 spp）：鬼影能量 GPU 对 CPU 差 0.6%，模糊后逐像素差 6%（噪点水平）；GPU 0.71 s，CPU 13.8 s。
  - 开鬼影时出瞳重要性采样自动关闭（与 OSL 相同）。
- **Neil 场曲**（`research/analysis/neil_field_curvature.py`）：从无穷远追整个光瞳，按最小光斑方差求各视场 X、Y 两向的最佳聚焦位置，对照专利设成的 X/Y 柱面像面。
  - 专利像面落在我们算出的 X、Y 最佳聚焦之间或附近，符号与量级一致。例如 50 mm 上边缘：X +0.131、Y +0.030，专利 +0.102 mm；85 mm 角落：+0.200 / +0.182，专利 +0.201 mm。这从像差层面独立验证了转录。
  - 平面传感器上，画面边缘的最佳聚焦在传感器前 0.1–0.2 mm，且有像散。f/3 时边缘弥散约 0.03–0.07 mm，4K 下角落约 6–12 px。这是这个设计本身的软角，保留。

## 6.9 0.8：发腮补偿、多层镀膜、采样、杂光标定、外部数据回归

- **发腮补偿**（`optics.compensator`、`tools/build_presets.py add_compensator`）
  - 原理：Wallin（US 2,890,622）/ Auto Panatar 的反向旋转弱柱面对。同号功率 P、轴向 ±θ 的两片叠加 = 水平 P(1 − cos2θ)、垂直 P(1 + cos2θ)，再配 −P 球面 → 水平 −P·cos2θ、垂直 +P·cos2θ，主截面始终在 x / y。
  - 模型（一阶等效）：变形器前一块 N-BK7 薄平板（5 mm，间隙 6 mm，不随对焦移动），前表面是曲率随对焦变化的马鞍面（水平 −φ、垂直 +φ）。φ 由对焦环行程 Δ1 经凸轮表决定，再乘补偿强度。对焦求解、出瞳表、炫光、后期色差图都通过 `layout()` 自动得到当前 φ，不改任何接口。
  - 凸轮表：每个距离三维牛顿解 (Δ1, Δ2, φ)：两截面合焦到无穷远像位 + 压缩比 = 无穷远压缩比。φ 最大 C 0.74 D、E 0.53 D、G 0.64 D。
  - 结果：完全补偿时最近对焦与 2 倍最近对焦处压缩比误差 < 0.02%；最近对焦 RMS 光斑 C 45 → 56 µm、E 35 → 37、G 25 → 33（几乎不变）；没有新的碰撞。C 的前组对焦行程从 19 mm 降到约 6 mm——这正是 Auto Panatar 的另一个好处。
  - 渲染实测（`tests/bl_mumps.py`，最近对焦处的发光圆盘）：补偿 0 → 宽高比 1.182（预测 1.186），补偿 1 → 0.989（预测 0.994）；CPU、GPU、Geometry 三条路径一致到 0.01%。
  - **意外的旁证**：补偿后 C/E/G 的对焦呼吸变成以垂直为主（E：水平 −5.6%、垂直 −31.6%），背景焦外从 1.35–1.40 变成 1.86–2.28 的竖椭圆。这两点都与公开描述一致（Panavision E 系列「vertical focus breathing」；Hawk：经典变形镜头主要垂直呼吸；经典 2:1 椭圆焦外）。未补偿时呼吸以水平为主，与这些描述不符。所以 0.8 把 C/E/G 默认设为完全补偿。
- **多层镀膜**（`optics.stack_reflectance`）：特征矩阵法，无吸收时每层矩阵形如 [[a, i·b], [i·c, d]]，只需实数运算。OSL、GPU、炫光通道三处同一实现。
  - 单层与旧 Airy 公式一致到 1e-16，玻璃侧 / 空气侧互易。
  - 宽带膜：外层 MgF₂ λ0/4、中层 2.05 λ0/2、贴玻璃层 1.38·√n_glass（λ0 处 L/M 两层零反射条件）λ0/4。λ0 = 520 nm 时 n_glass 1.52–1.95 上 450–650 nm 平均 0.16–0.17%，420–680 最大 0.5–1.3%。
  - Neil 50 的鬼影能量比单层弱 12 倍，颜色由蓝紫变成品红 / 琥珀。GPU 与 CPU 鬼影能量差 0.7%。
- **出瞳采样表**：实测带光占比的损失几乎全部来自盒子的余量（1.5 个网格间距 + 3%，网格 36），对焦状态 / 波长取并集几乎不损失。
  - 网格加密到 72、余量 1% → 平均 0.54 → 0.62–0.74，没有每采样开销。表的追迹加了剔除与解析求交（快 4.5 倍），预设 × 4 种画幅的表随包分发（128 KB）。
  - **没有做 ROADMAP 8.1 的牛顿瞄准光阑**：单一状态的紧包围盒上限也只有 0.72–0.91，牛顿瞄准每采样要多 3–9 次追迹，收益抵不过开销。
- **波长分层（GPU）**：第二处补丁把 Cycles 的 time 随机数传给相机（不开运动模糊时它没人用，且与出瞳两维同属一个三维 Sobol 点）。
  - 同 spp 色噪低 2.1 / 2.4 / 2.7 倍（16 / 64 / 256 spp），平均颜色差 0.04%。
  - CPU / OSL 拿不到这一维（OSL 相机只有两维随机数），仍用哈希。
- **杂光标定**：见 §5 第 13 条。核心幂律 r0 = 对角线 0.4%、p = 2.6，均匀项 50%，黑斑直径 10% 画面高——都是假设，ISO 9358 没有规定黑斑大小。
- **外部数据回归**（`tests/test_reference.py`）：最近对焦距离（Panavision 公布值）、近摄压缩比（ARRI MA）、焦外形状（前置 / 后置）、呼吸方向。
- **Geometry 模式**：补上光圈网格；法线精度两处修正。残差与排查记录见 §5 第 14 条。

## 6.10 调研：Blender 5.0–5.3 的新功能（2026-10-19）

依据：5.0–5.3 发布说明、本机 Blender 5.3.0 Beta 的 Cycles 内核源码与 Python API（[src] = 本机源码 / API 亲自核对过）。

**风险（必须处理）**
- **5.3 的色散会与我们的波长重复加权。** 5.3 给 Principled BSDF 加了透射色散（`Transmission Dispersion Scale / Abbe Number` [src]）。实现是「每条路径一个波长」：第一次碰到有色散的表面时，用 `PRNG_BOUNCE_NUM + PRNG_WAVELENGTH` 的随机数抽波长，路径权重乘 `wavelength_to_rgb_d65(λ)/pdf` 并置 `PATH_RAY_SPECTRAL`（`integrator/path_state.h`、`shade_surface.h` [src]）。我们的相机已经按自己的 λ 与传感器曲线加过权，两者波长不同、权重叠两次 → 场景里有色散玻璃时颜色错。GPU 路径能修（第三处补丁：相机用同一个随机数抽 λ、按 Cycles 的约定加权并置 `PATH_RAY_SPECTRAL`）；OSL / CPU 路径读不到也设不了这个标志，修不了，只能提示。Glass BSDF 没有色散输入 [src]。
- 工作色彩空间（5.0 可选、5.3 每项目 OCIO / ACES）：我们的传感器 RGB 高斯曲线和 numpy 后期默认 Linear Rec.709，换色彩空间时颜色会偏。
- 内核补丁按原文逐字匹配：5.2 加了纹理缓存（`r_cache_miss`），5.3 的锚点仍匹配 [src]；每个点版本都要对比 `camera/camera.h` 与 `integrator/init_from_camera.h`。

**机会**
1. **合成器效果栈（5.3）**：`scene.compositor_effects` [src] 让插件挂自己的效果而不覆盖用户的合成节点树；Glare 有 Kernel 模式（输入自定义卷积核）、有 Convolve 节点 [src]、Map UV 支持双三次。星芒（核图仍由我们的 FFT 生成）、杂光（Convolve）、横向色差（三张 ST 图 + Map UV）都能变成 GPU 合成、实时可调；正向鬼影仍由 numpy 算成一张图叠上去。需要逐项对照 numpy 结果。
2. **实时预览**：EEVEE + 合成器按 ST 图扭曲（加过扫描），近似看到压缩、畸变、色差、炫光。5.3 的 EEVEE 支持全景相机（含 Fisheye Lens Polynomial [src]），但它是旋转对称的，表达不了变形畸变，用处有限。
3. **Geometry 模式的真色散**：镜片网格改用 Principled（n_d / V_d 直接来自处方）即可有横向与纵向色差——但要先解决上面的波长问题。
4. Python：`bpy.app.cachedir`（5.1，放内核拷贝与出瞳表缓存）、`exit_pre` 处理器、`gpu.init()`（5.2，后台也能用 GPU 模块）+ `GPUStorageBuf`（5.3）[src] → numpy 后期可以改成 Metal 计算着色器；5.3 内置 OpenEXR 模块（写 ST 图、炫光层）。

**仍然没有**：Metal 上的 OSL（GPU OSL 仍只有 OptiX，`_cycles.init` 补丁仍必要）；HIP / oneAPI 自定义相机；OSL 相机更多随机维度（仍只有 2 维，没有时间 / 波长）；自定义相机的 Vector pass（源码 `camera.h` 里仍是 TODO [src]）；多层薄膜；Glass BSDF 色散。

## 6.12 0.8.2：与 Blender 5.3 色散共用波长、工作色彩空间、补丁漂移检查

- **问题实测**（`tests/bl_spectral_glass.py`，白色天空透过一块 5.3 色散玻璃，Abbe 20）：CPU / OSL 路径平均颜色 (0.79, 0.79, 0.63)，偏色 14%，色噪是无色散玻璃的 2.2 倍——不只是噪点，是明显的偏色（镜头与玻璃各抽一个波长、颜色加权两次）。
- **GPU 修法**（内核补丁共七处，`gpukernel.PATCH_SITES`）：相机与色散材质用**同一个随机数、同一个映射**（Cycles 的 `sample_wavelength`）得到同一个 λ，路径置 `PATH_RAY_SPECTRAL`（Cycles 不再在玻璃处另加权重）。随机数：不开运动模糊时取 Cycles 的 time 维（与出瞳联合分层），`shader_data.h` 的 `shader_setup_wavelength` 按同一规则取。修后：偏色 0.2%，色噪 1.04 倍。
- **两种模式**：只有场景里真有色散材质时才进入「共用模式」（由 `rig.dispersive_materials` 判断，每次渲染开始同步内核头文件）；默认模式保持 0.8 的逆 CDF 采样表。原因：Cycles 的波长映射按 D65 亮度分配，蓝端概率低，蓝通道权重尖 → 同 spp 色噪高 1.2 倍（`bl_spectral` 实测 `shared_cost_64` = 1.2）。默认模式与 0.8 逐位相同（16 spp 色噪 3.70）。
- **为什么颜色权重不用 CIE 色匹配**：CIE → RGB 有负瓣，实测每样本色度标准差约 1.9–2.25（三条传感器高斯 1.1–1.3），同 spp 色噪约高 1.7 倍；在 Cycles 的映射下用 CIE 权重，16 spp 色噪 9.65（传感器权重 5.88，0.8 默认 3.70）。所以保留传感器响应，只把它定义在 Rec.709 原色下再换到工作色彩空间（GPU：Cycles 的 `rec709_to_rgb`；OSL：插件用 OpenColorIO 算矩阵写入 `rec_*` 参数）。ACEScg 场景实测：色散开 / 关平均颜色差 < 0.7%（与 Rec.709 相同）。
- **CPU / OSL 修不了**（OSL 相机读不到也设不了路径波长）：`bl.diagnose()` 发现色散材质时给出 `spectral_conflict_cpu` 警告和三种修法。
- **补丁漂移**：`tests/test_kernel_patch.py`（quick 级）检查本机 Blender 的七处原文，并在内存里打一遍补丁；`check_compatible()` 的失败信息逐处列出。
- **教训**：内核拷贝目录只按 `PATCH_VERSION` 命名时，改了补丁文本却没改版本号，会继续用旧拷贝（本次一度测出「分层采样变差 1.4 倍」，其实是旧补丁）。现在目录名含全部补丁文本的哈希。
- 光谱数据：`tools/extract_cie.py` 从 Cycles 的 `tables.h` / `colorspace.h` 取出 CIE 表与采样器常数（`blenderlens/spectral/cie_d65.json`）；`blenderlens/spectral.py` 是 Python 参考实现。出瞳表波长范围扩到 380–780 nm（表版本 4）。
